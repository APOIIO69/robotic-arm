**Версия:** 1.0  
**Дата:** 16.05.2026  
**Статус:** Draft для утверждения

## 1. Общие сведения

### 1.1 Назначение
Мобильное приложение RoboArm предназначено для мониторинга состояния и оперативного управления промышленными роботами на производстве. Оператор видит телеметрию в реальном времени, получает уведомления об аварийных ситуациях и управляет роботами через интерфейс приложения.

### 1.2 Платформа
- **iOS** 16+, **Android** 12+
- Технологии реализации: на усмотрение команды (React Native / Flutter)
- Ориентация: только портретная

### 1.3 Роли пользователей (MVP)
| Роль | Описание |
|---|---|
| **Оператор** | Основной пользователь. Мониторинг, управление, реагирование на ошибки |
| *(Администратор)* | За рамками MVP. Управление учётными записями, настройка порогов |

## 2. Архитектура навигации

### 2.1 Структура экранов

```
TabBar (глобальный, 3 вкладки):
├── [Главная]
│   ├── Дашборд (статистика + список линий)
│   ├── → Детализация линии
│   │   └── → Карточка робота
│   │           ├── Телеметрия (вкладка)
│   │           └── Управление (вкладка)
│   ├── → Уведомления (отдельный экран)
│   └── → Настройки (отдельный экран)
├── [Поддержка]  ← MVP: заглушка
└── [Отчёты]     ← MVP: заглушка
```

### 2.2 Навигация
- **Back** — кнопка в хедере каждого вложенного экрана
- **TabBar** — присутствует на всех экранах
- **Фильтр** — не меняет экран, фильтрует текущий список

## 3. Экраны

---

### 3.1 Экран «Главная» (Home)

#### Хедер
| Элемент | Описание |
|---|---|
| Аватар / инициалы | Кружок с инициалами пользователя. Нажатие — переход в профиль *(post-MVP)* |
| Строка поиска | Фильтрует список линий в реальном времени по названию |
| Кнопка настроек | Переход на экран «Настройки» |

#### Дашборд быстрого просмотра
4 карточки в сетке 2×2:

| Карточка | Значение | Действие |
|---|---|---|
| Критические ошибки | Кол-во устройств с `status = critical` | Фильтр списка → critical |
| Предупреждения | Кол-во активных предупреждений | Фильтр списка → warning |
| Всего роботов | `онлайн / всего` | Нет действия |
| В ремонте | Кол-во устройств на обслуживании | Нет действия |

#### Фильтры
Три кнопки-таба: **Все** · **Критические** · **Предупреждения**  
Фильтруют список линий по worst-case статусу линии.

#### Список линий
- Каждая карточка: название линии + текстовое описание статуса + 3 цветовых индикатора (critical / warning / ok)
- Нажатие на карточку → экран «Детализация линии»
- Пустой список при фильтрации → текст-заглушка

#### Состояния экрана
| Состояние | Описание |
|---|---|
| Загрузка | Скелетон-заглушки карточек |
| Данные получены | Стандартное отображение |
| Нет соединения | Баннер с ошибкой соединения + кнопка повтора |
| Пустой список | Подпись «Нет линий по выбранному фильтру» |

### 3.2 Экран «Детализация линии»

#### Хедер
| Элемент | Описание |
|---|---|
| Кнопка «Назад» | Возврат на Home |
| Название линии | Текст, ellipsis при переполнении |
| StatusPill | Текущий статус линии |

#### Поиск
Поле поиска роботов по имени в пределах линии.

#### Фильтры
Аналогичны Home: **Все** · **Критические** · **Предупреждения** (по статусу робота).

#### Список роботов
Каждая карточка содержит:
- Имя робота
- Модель (вторичный текст)
- Иконка типа устройства
- Статус ошибки или «Работает штатно»
- StatusPill (состояние)
- ChevronRight

Нажатие → экран «Карточка робота».

> **Post-MVP:** долгое нажатие → модальное окно быстрой сводки (ошибки за N часов, датчики вне нормы).

#### Состояния
Аналогичны Home. Пустой список при фильтре → заглушка.

### 3.3 Экран «Карточка робота»

#### Хедер
| Элемент | Описание |
|---|---|
| Кнопка «Назад» | Возврат к списку роботов линии |
| Имя робота | Основной заголовок |
| Модель | Подзаголовок (вторичный цвет) |
| StatusPill | Текущий статус |

#### Баннер ошибки
Показывается, если `robot.errorText != null`. Содержит иконку и текст ошибки на фоне `statusDim`.

#### Вкладки
Показываются только если у робота есть панель управления (`axes.length > 0` или специальные кнопки).  
Две вкладки: **Телеметрия** · **Управление**

---

#### Вкладка «Телеметрия»

Сетка плиток датчиков (2 колонки).  
Каждая плитка (`SensorTile`) отображает:
- Иконку типа датчика
- Название датчика
- Текущее значение + единицу измерения (монопространственный шрифт)
- Мини-бар заполнения (если есть `normalMin`/`normalMax`)
- StatusDot (индикатор нормы)

Набор датчиков полностью определяется конфигурацией конкретного робота.  
Порядок отображения плиток = порядок в массиве `sensors[]`.

> **Post-MVP:** нажатие на плитку датчика → детальный график изменения за последние 24 ч.

---

#### Вкладка «Управление»

**Кнопка аварийной остановки** (всегда первая):
- Состояние «активна»: красный фон, текст «АВАРИЙНАЯ ОСТАНОВКА»
- Состояние «остановлен»: нейтральный фон, текст «ВОЗОБНОВИТЬ РАБОТУ»
- Действие: посылает команду `ESTOP` / `RESUME` на устройство

**Дополнительные кнопки** (зависят от типа робота):
- Отображаются, только если соответствующий флаг `true` в конфиге робота
- Примеры: клешня (разжать / захват), горелка (вкл/выкл), распылитель, вакуум

**Слайдеры осей**:
- Один слайдер на каждую ось из `axes[]`
- Диапазон: `[axis.min, axis.max]` в градусах
- Текущее значение: отображается справа от названия оси
- Недоступны (opacity 0.4) при активной аварийной остановке
- Изменение слайдера → команда на устройство с дебаунсом 150мс

### 3.4 Экран «Уведомления»

Хронологический список событий.

Фильтрация: по типу (все / критические / предупреждения).

> **Post-MVP:** пагинация, push-уведомления, группировка по устройству.

## 4. Модели данных

### 4.1 Line (Производственная линия)
```typescript
interface Line {
  id:          number;
  name:        string;        // «Линия A — Сварка»
  description: string;        // Человекочитаемый статус
  hasCritical: boolean;
  hasWarning:  boolean;
  allOk:       boolean;
  status:      Status;        // worst-case по роботам
  robots:      Robot[];
}
```

### 4.2 Robot (Робот)
```typescript
interface Robot {
  id:          number;
  name:        string;        // «KUKA KR 210 #1»
  model:       string;        // «KUKA KR 210 R2700»
  type:        string;        // произвольный тип: «welding_arm», «inspection», ...
  status:      Status;        // worst-case по датчикам
  statusText:  string;        // «Работает штатно» / «Критическая ошибка»
  errorText:   string | null; // краткое описание ошибки
  sensors:     Sensor[];      // набор датчиков специфичен для каждого типа
  axes:        Axis[];        // [] если нет управления осями
  // Флаги специальных кнопок управления:
  hasGripper?: boolean;
  hasTorch?:   boolean;
  hasSpray?:   boolean;
  hasVacuum?:  boolean;
  // ... расширяемо новыми флагами
}
```

### 4.3 Sensor (Датчик)
```typescript
interface Sensor {
  id:          string;        // уникальный идентификатор внутри робота
  label:       string;        // «Температура J1»
  value:       number;        // текущее значение
  unit:        string;        // «°C», «А», «Нм», «мм/с», ...
  type:        SensorType;    // определяет иконку и визуализацию
  status:      Status;        // ok / warning / critical
  normalMin?:  number;        // нижняя граница нормы (опционально)
  normalMax?:  number;        // верхняя граница нормы (опционально)
}

type SensorType =
  | 'temperature' | 'torque'   | 'current'  | 'counter'
  | 'percent'     | 'pressure' | 'force'    | 'weight'
  | 'speed'       | 'vibration'| 'distance' | 'power' | 'flow'
  | string;  // расширяемо: неизвестный тип → дефолтная иконка
```

### 4.4 Axis (Ось)
```typescript
interface Axis {
  name:  string;  // «J1» – «J6»
  min:   number;  // минимальный угол (градусы)
  max:   number;  // максимальный угол (градусы)
  value: number;  // текущее положение
}
```

### 4.5 Status
```typescript
type Status = 'ok' | 'warning' | 'critical' | 'offline';
```

### 4.6 Notification (Уведомление)
```typescript
interface Notification {
  id:      number;
  type:    'critical' | 'warning';
  robot:   string;    // имя робота
  line:    string;    // имя линии
  message: string;    // текст события
  time:    string;    // «2 мин назад» (относительное)
  ts:      number;    // Unix timestamp для сортировки
}
```

## 5. Гибкая система датчиков

**Ключевое требование:** набор датчиков не фиксирован на уровне UI. Каждый робот имеет произвольный массив `sensors[]`, который приходит с сервера и рендерится динамически.

### Правила вычисления статуса датчика на сервере
```
if (normalMin != null && value < normalMin) → warning или critical
if (normalMax != null && value > normalMax) → warning или critical
иначе → ok
```

Пороги `warning` и `critical` задаются в настройках системы (post-MVP: через экран «Настройки → Пороги нормы датчиков»).  
В MVP: сервер присылает `status` уже вычисленным.

### Добавление нового типа датчика
1. Определить `type: string` (новый ключ)
2. Добавить иконку в словарь `SensorIcon` на клиенте
3. Всё остальное (плитка, бар, статус) работает автоматически

### Добавление новой спецкнопки управления
1. Добавить флаг в `Robot`: `hasXxx: boolean`
2. Добавить условный рендер кнопки в панель управления
3. Кнопка отправляет команду `ROBOT_ACTION` с `action: 'xxx'`

## 6. API-контракты (предварительные)

### 6.1 Получение списка линий
```
GET /api/lines
Authorization: Bearer {token}

Response 200:
{
  "lines": Line[]
}
```

### 6.2 Получение роботов линии
```
GET /api/lines/{lineId}/robots

Response 200:
{
  "robots": Robot[]
}
```

### 6.3 Получение телеметрии робота
```
GET /api/robots/{robotId}/telemetry

Response 200:
{
  "robot":   Robot,
  "sensors": Sensor[],
  "axes":    Axis[]
}

// MVP: polling каждые 5 секунд
// Post-MVP: WebSocket / SSE
```

### 6.4 Получение уведомлений
```
GET /api/notifications?limit=50&offset=0

Response 200:
{
  "notifications": Notification[],
  "total": number
}
```

### 6.5 Команда управления роботом
```
POST /api/robots/{robotId}/command
{
  "type":  "ESTOP" | "RESUME" | "SET_AXIS" | "ROBOT_ACTION",
  "axis"?: string,   // для SET_AXIS
  "value"?: number,  // для SET_AXIS (градусы)
  "action"?: string  // для ROBOT_ACTION: "gripper_open", "torch_on", ...
}

Response 200: { "ok": true }
Response 4xx/5xx: { "error": string }
```

### 6.6 Аутентификация
```
POST /api/auth/login
{ "username": string, "password": string }

Response 200:
{ "token": string, "user": { "name": string, "initials": string } }
```

## 7. Нефункциональные требования

### 7.1 Производительность
- Список линий (до 20 строк): рендер < 100мс
- Список роботов (до 50): рендер < 150мс
- Телеметрия polling: интервал 5 сек, timeout 3 сек

### 7.2 Оффлайн
- При отсутствии соединения: показывать последние кешированные данные + баннер «Нет подключения»
- Команды управления при оффлайне: блокировать + показывать ошибку

### 7.3 Безопасность
- Все запросы: HTTPS
- Токен хранить в Keychain (iOS) / Keystore (Android)
- Сессия: автологаут через 8 часов бездействия

### 7.4 Доступность
- Минимальный размер нажимаемого элемента: 44×44px
- Цветовые статусы всегда сопровождаются текстовой меткой (не только цвет)

## 8. Объём MVP vs Post-MVP

### В MVP (v1)
- [x] Авторизация (логин/пароль)
- [x] Главный экран: дашборд + список линий
- [x] Детализация линии: список роботов
- [x] Карточка робота: телеметрия + управление
- [x] Гибкая система датчиков (любой набор через API)
- [x] Управление осями (слайдеры)
- [x] Аварийная остановка
- [x] Спецкнопки по флагам робота
- [x] Уведомления (список)
- [x] Настройки: смена темы
- [x] Тёмная / светлая тема

### Post-MVP (v2+)
- [ ] WebSocket для телеметрии в реальном времени
- [ ] Push-уведомления (APNS / FCM)
- [ ] Графики истории датчиков за 24 ч (по нажатию на плитку)
- [ ] Быстрая сводка по роботу (долгое нажатие на карточку)
- [ ] Редактирование профиля, аватар
- [ ] Статистика оператора (устранённые ошибки)
- [ ] Двухфакторная аутентификация
- [ ] Фильтрация уведомлений + пагинация
- [ ] Экран «Поддержка» (чат с техподдержкой)
- [ ] Экран «Отчёты» (экспорт, история работы)
- [ ] Настройка порогов нормы датчиков
- [ ] Административная панель (управление пользователями)
- [ ] Поиск по отчётам
