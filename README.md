Моя команда будет заниматься разработкой двухосевой роборуки в качестве курсового проекта по дисциплине Микропроцессорная техника на 2 курсе ВУЗа. Сейчас, нам нужно выбрать симуляционную среду, чтобы сделать там прототип роборуки, после чего написать код для управления ей и протестировать его в этой симуляционной среде.

Я подробнее распишу задачу:

Прототип роборуки должен быть достаточно примитивным, самые основные компоненты: оси, электродвигатели, платы управления электродвигателями (нужны будут отдельные, чтобы подавать повышенное напряжение при получении сигнала от главной управляющей платы), главная управляющая плата (можно что-то стандартное по типу STM32), общение с сервером управления через эдж-компьютинг на RPi.

Роборука должна иметь возможность двигаться вертикально и горизонтально и иметь на конце щуп, силу сжатя которого так же хотелось бы контроллировать. Нужно будет написать код, который будет решать кинетическое управление, подавая определенное напряжение на электродвигатели, чтобы они двигались на определенное кол-во градусов. Дополнительной важной задачей будет передача статистических данных hardware (температура, напряжение плат, ЭД, ...) на сервер для их дальнейшего анализа (поиск поломок, необходимость в обслуживании, ...).

Техническое задание на разработку симуляционного прототипа двухосевой роборуки

1. Назначение документа
Документ описывает технические требования к курсовому проекту по дисциплине "Микропроцессорная техника". Проект включает симуляцию физики манипулятора, разработку прошивки низкого уровня и создание распределенной системы управления.
2. Архитектура программно-аппаратного комплекса
Система разделена на два изолированных контура, взаимодействие между которыми осуществляется по локальной сети:
2.1. Локальный контур симуляции. Реализуется в среде Webots. Включает физическую модель роборуки и низкоуровневый C-контроллер, выполняющий роль микроконтроллера STM32.
2.2. Серверный контур управления. Реализуется в виде Docker-контейнера с установленным стеком ROS 2 и micro-ROS Agent. Контейнер выполняет роль edge-компьютера Raspberry Pi.
3. Требования к симуляционной модели (Webots)
3.1. Кинематическая схема: два активных шарнира, обеспечивающих позиционирование звеньев в двух плоскостях.
3.2. Рабочий орган: щуп на конце второго звена.
3.3. Сенсорика: датчики положения на каждом шарнире для считывания текущего угла поворота.
3.4. Актуаторы: узлы моторов с активированной функцией обратной связи по усилию для считывания текущего крутящего момента. Управление физическим движением осуществляется через прямое задание крутящего момента в коде.
3.5. ТЗ. Перед разработкой модели самой руки, нужно составить документ, где будут описываться желаемые ТТХ прототипа, чтобы потом, соответственно этим характеристикам выбрать нужные компоненты прототипа. Т.к. стенд учебный, требования должны быть умеренно простые.
4. Требования к низкоуровневому контроллеру
4.1. Среда исполнения: C-контроллер Webots.
4.2. Сетевое взаимодействие: статическая линковка с клиентской библиотекой micro-ROS.
4.3. Сбор данных: циклический опрос датчиков положения, расчет угловой скорости, опрос реальных физических усилий моторов.
4.4. Публикация телеметрии: упаковка собранных данных в стандартные структуры сообщений и отправка в топики micro-ROS.
4.5. Прием команд: подписка на топики целевых моментов от сервера и их применение к узлам моторов.
5. Требования к серверному ПО (Docker)
5.1. Окружение: Dockerfile, содержащий базовый образ ROS 2, скомпилированный micro-ROS Agent и зависимости для сборки серверного кода.
5.2. Сетевая инфраструктура: контейнер должен иметь проброшенные порты для беспрепятственного прохождения UDP-трафика от симулятора.
5.3. Вычислительный блок: ROS 2 нода, реализующая алгоритмы прямой и обратной кинематики.
5.4. Блок управления: ПИД-регулятор для расчета управляющих воздействий на основе рассогласования текущих координат из телеметрии и заданных целевых точек.
6. Требования к тестированию
6.1. Подтверждение точности позиционирования щупа по заданным координатам.
6.2. Настройка коэффициентов регулирования для исключения критических осцилляций при движении.
6.3. Подтверждение стабильности сетевого UDP-обмена между хост-системой с Webots и Docker-контейнером с ROS 2.
