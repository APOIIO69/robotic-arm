# Обоснование архитектурных решений

Этот документ описывает выбор технологий для курсового проекта "Двухосевая роборука".

## 1. Среда симуляции: Webots vs Gazebo
**Выбор:** Webots
**Обоснование:**
- **Простота настройки:** Webots поставляется как единый бинарный пакет с отличной документацией. Gazebo часто требует сложной настройки окружения (особенно с ROS 2).
- **Встроенные сенсоры:** Webots предоставляет высокоуровневые API для датчиков крутящего момента и положения "из коробки" без необходимости написания сложных плагинов.
- **Производительность:** Webots лучше оптимизирован для работы на обычных ПК без мощных GPU, что критично для учебного проекта.

## 2. Связующее ПО: micro-ROS
**Выбор:** micro-ROS
**Обоснование:**
- **Стандарт индустрии:** micro-ROS позволяет использовать парадигму ROS 2 даже на микроконтроллерах с ограниченными ресурсами.
- **Единая экосистема:** Использование micro-ROS позволяет бесшовно интегрировать контроллер Webots (симулирующий STM32) в общий граф ROS 2.
- **UDP Транспорт:** Использование UDP обеспечивает минимальные задержки при передаче телеметрии, что важно для контуров управления.

## 3. Язык программирования контроллера: C
**Выбор:** Чистый C
**Обоснование:**
- **Близость к железу:** Позволяет максимально достоверно симулировать разработку под STM32.
- **Статическая линковка:** Библиотеки micro-ROS для встраиваемых систем написаны на C, что исключает проблемы совместимости.

## 4. Контейнеризация: Docker
**Выбор:** Docker
**Обоснование:**
- **Изоляция окружения:** Позволяет запустить ROS 2 Humble со всеми зависимостями на любой ОС (Linux/Windows/Mac) без конфликтов с локальными библиотеками.
- **Воспроизводимость:** Гарантирует, что у всех участников команды будет идентичное серверное окружение.
