# Сетевая инфраструктура и протоколы

Система представляет собой распределенную сеть управления, разделенную на два уровня.

## 1. Физический уровень сети (в симуляции)
- **Host-to-Docker:** Виртуальный сетевой мост (Bridge).
- **Порты:**
  - UDP 8888: Основной канал micro-ROS Agent.
  - UDP 9999: Канал для отладочного вывода (логи).

## 2. Протоколы передачи данных
### micro-ROS (основной)
Используется протокол **XRCE-DDS** (eXtremely Resource Constrained Environments DDS).
- **Преимущества:**
  - Минимальный оверхед на заголовки пакетов.
  - Поддержка модели "издатель-подписчик".
  - Возможность работы без полноценного IP-стека (в реальном железе через Serial/UART).

### Логика обмена
1. **Телеметрия (Cyclic):** Контроллер раз в 10 мс упаковывает значения `float32` (угол, ток) в структуру `JointState` и отправляет UDP-пакет.
2. **Команды (Event-driven):** При получении новой цели в ROS 2, сервер формирует пакет с целевыми значениями и отправляет его контроллеру.
3. **Keep-alive:** micro-ROS Agent постоянно мониторит состояние клиента. При обрыве связи (например, закрытие Webots) серверная нода переходит в режим "Safe Stop".

## 3. Топология
Топология "Звезда", где **micro-ROS Agent** в Docker является центральным узлом, координирующим трафик между низкоуровневым контроллером и остальными нодами ROS 2 (управление, API, визуализация).
